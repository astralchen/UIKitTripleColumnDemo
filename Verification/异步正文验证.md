# 异步正文晚返回验证（2026-10-27）

实现位于 `Sources/RouteModel/ArticleBodyLoader.swift`，由默认三栏示例的 `refresh()` 同步安装内容上下文。注释稿第 21.2 节包含流程图，第 22 节包含合并后的完整 iOS 15 代码，第 23.1 节同步实际运行的正文测试。

## 提交结果的条件

每次加载生成 UUID；捕获分类 ID、文章 ID 与 RouteLedger.contentVersion。只有当前请求 ID 和整个内容上下文均匹配，响应才能结束 loading 或更新正文 / 错误。删除或切换分类立即清空正文及凭证，再取消任务。旧成功、错误和取消均不得清理新任务。校验和提交在 MainActor 上连续完成，中间没有 await。

contentVersion 是本地内容上下文的代次，不是服务端修订号。相同文章重试可保持内容版本，但必须使用新请求 ID。纯返回与宽窄布局变化保留有效上下文，不会因加载完成改变 route。网络缓存新鲜度仍须由实际服务端 revision / ETag 策略保证。

## 模型与异步测试：通过

`swift test`：25 项通过，0 失败，包括原有 17 项与新增 8 项。见 `异步正文模型测试.log`。

新增测试的可控服务故意忽略任务取消，使用 continuation 等待请求登记并指定响应顺序。每次释放响应后等待提交 / 丢弃回调完成，不用固定 sleep 作为业务断言依据。

| 场景 | 断言 |
| --- | --- |
| A→B，B 先成功、A 后成功 | 保留 B 正文 |
| A 的旧失败 / 取消在 B 加载期间到达 | B 仍 loading，当前请求仍为 B |
| 同文章、同版本重复刷新 | 请求 ID 不同，只接受后一次 |
| A→B→A | 第一笔 A 和 B 均不能写入新 A |
| 返回手势和布局中删除文章，返回分别完成 / 取消 | 正文 idle、选择 nil、route=list |
| 分类改变且文章 ID 被复用 | 旧分类响应无效，新分类响应有效 |
| 返回成功并切换布局，文章仍有效 | 正文可完成，但 route 保持 list |
| 当前失败、取消与再次重试 | 正确退出 loading，重试可成功 |
