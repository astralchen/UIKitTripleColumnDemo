# 内容失效与导航 / 布局交错验证

执行日期：2026-10-27。目标是区分“取消一次返回”与“恢复一份已经失效的数据”，防止删除文章或切换分类后，旧回调重新进入无效详情。

## 实现规则

- `ReadingLibrary` 校验分类存在、文章存在且属于该分类；无效选择立即清空。
- `contentVersion` 绑定选择上下文。有效选择发生变化时递增；删除无关文章只更新数据源，不打断有效导航。
- 导航记录同时携带 `transactionID`、`layoutVersion` 和 `contentVersion`。内容已失效时，旧完成 / 取消回调只解除等待，不再应用旧起点或目标。
- `pending` 保留到 UIKit 转场结束；期间不强行开启另一次 `show` / `pop`。待导航和布局均结束，再根据最新的有效 route 恢复。
- 页面出现凭证同时校验布局与内容版本，并确认目标在当前数据中有效。
- 明确切换分类的策略是进入新分类列表；删除当前文章则退回当前有效分类的列表；分类也失效时回到分类页。

## 验证范围

模型测试新增 9 项，加上原有 8 项，共 17 项：

1. 删除选中文章后，旧手势完成 / 取消均不能恢复详情。
2. 删除与布局交错，布局先结束 / 导航先结束均能恢复有效列表。
3. 切换分类后，旧成功返回到分类页的目标不能覆盖新列表意图。
4. 当前分类被删除，清空分类和文章，回退分类页。
5. 删除无关文章不打断仍有效的返回。
6. 恢复完成后，旧 `didAppear` 的内容版本仍不匹配，不能写回详情。
7. 被删除 ID 重新加入数据源，不自动恢复选择。
8. 正在恢复列表时分类再次失效，最终校正到分类页。
9. 初始化快照中的分类 / 文章归属错误，以及分类页删除已选文章的策略。

新增 5 项 UI 用例，加上原有 5 项回归：

- 删除文章后取消返回，实际结果是 `cancelled`，但 route 为 `list`，文章选择为空。
- 删除文章后完成返回并展开，重新折叠仍是有效列表。
- 切换分类后取消返回并展开，保留新分类，清空旧文章。
- 手指拖动期间删除文章并展开，按系统实际结果结束转场，但不恢复已删除详情。
- 实际列展开回调期间删除文章，确认数据事件没有被导航忙碌条件丢弃。

UI 断言不仅检查状态字符串，还检查旧正文消失、最新列表条目以及恢复后目标页面可点击。`invalidNav` / `invalidLayout` 计数证明数据失效发生在未完成的导航 / 布局中，`ignoredContent` 证明旧结果已被接收而没有覆盖修正位置。

## 边界

- UI 使用 iPadOS 27.0、iPad Pro 13-inch (M5) 模拟器，公开尺寸类别覆盖和容器宽度触发布局变化。
- 未执行 iOS 15 运行时、全部真机 / 多窗口矩阵、动画每一帧的快照内容检查。
- 分类删除、无关文章删除、同 ID 重新出现和恢复中二次失效由模型测试覆盖；不冒充对应的真实 UI 自动化覆盖。
- 本例没有网络正文加载；`catalogWasReplaced` 接收的数据快照需要数据层保证新鲜度，未实现服务器版本排序、权限验证或持久化同步。
- 内容失效的策略是应用层设计，UIKit 的 `isCancelled` 仅表示交互转场是否取消，不会撤销业务删除事件。
