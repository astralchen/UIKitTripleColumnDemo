## 交错测试如何避免误判

UI 测试使用系统边缘返回识别器和真实触摸拖动。验证外壳在真实交互转场开始 / 交互决定后，通过公开容器宽度和尺寸类别覆盖触发展开，**不直接调用模型完成方法，也不伪造 `isCancelled`**。

- `overlap > 0` 证明布局开始时模型中仍有未结束的导航事务。
- 完成分支明确断言 `result=completed` 与 `route=list`。
- 取消分支明确断言 `result=cancelled` 与 `route=detail`。
- 手指拖动期间展开的用例接受 UIKit 实际完成或取消的结果，但必须满足相应的 route；不能用拖动距离代替系统结果。
- 再次折叠后，断言目标页面的单元格可点击，避免只验证状态字符串。
- 模型另行验证“展开又折叠，最终返回结果才到达”的精确事件顺序；此矩阵不冒充同样顺序的真实手势 UI 验证。

## 初次失败及修正

[首次执行](UI-首次执行.json)为 2 通过、3 失败：

1. 普通取消用例的旧正则要求取消计数位于字符串末尾；新增诊断字段后造成误报。修正为允许后续字段。
2. 两个决定后展开用例在交互状态回调内同步切换布局，出现崩溃。调用栈位于 UIKit 执行交互回调期间。测试外壳改为下一轮主队列执行触发动作，退出当前回调栈后仍由 `overlap > 0` 验证交错；重跑五项测试全部通过。

该修正没有放宽完成 / 取消分支断言，也没有用模型事件替换系统手势。业务恢复本身通过导航结果及布局完成条件驱动，不使用固定延时猜测动画结束。
